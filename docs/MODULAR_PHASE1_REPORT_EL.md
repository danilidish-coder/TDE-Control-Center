# CONTROL CENTER — Αναφορά Φάσης 1

## Πεδίο και προστασία λειτουργικής έκδοσης

Η υλοποίηση βρίσκεται αποκλειστικά στο `refactor/modular-phase1`, με αφετηρία το `cade2e152c1044a2d9ce8050eef299ed4536c58b`. Η ενσωματωμένη έκδοση παραμένει `1.0.14`. Δεν άλλαξαν `main`, tags, παραγωγικά releases ή λειτουργικά EXE. Δεν έγινε μεταφορά πραγματικών δεδομένων, αλλαγή schema ή συγχώνευση των δύο διαδρομών εφαρμογής.

Αμετάβλητα παραμένουν: `main.py`, `control_center_autonomous.py`, όλος ο φάκελος `modules/`, ο πυρήνας SQLite/κλειδωμάτων/διαδρομών, τα πρότυπα και οι εικόνες, τα shared assets, οι εξαρτήσεις και το υπάρχον PyInstaller spec. Η ασυμφωνία εκδόσεων σε παλιότερα έγγραφα και assertions δεν διορθώθηκε μέσα στην αναδιοργάνωση.

## Αλλαγές

- Μεταφέρθηκαν 29 υπάρχουσες υλοποιήσεις στις νέες λειτουργικές ενότητες, την υποδομή και τα κοινά βοηθήματα. Πλήρης αντιστοίχιση: `modular-phase1-moves.json`.
- Οι παλιές διαδρομές εισαγωγής διατηρούνται ως aliases στο ίδιο module object. Δεν περιέχουν δεύτερη υλοποίηση και διατηρούν τη λειτουργία monkeypatches των υφιστάμενων δοκιμών.
- Το `MainWindow` περιορίστηκε από 328 σε 113 γραμμές. Η υπάρχουσα διάταξη και η ζωγραφική κεφαλίδας απομονώθηκαν σε `ui/shell.py` και `ui/header.py`.
- Η δημιουργία υπηρεσιών μεταφέρθηκε στο `bootstrap.py`, με διατήρηση της αρχικής σειράς δημιουργίας και backup.
- Το `registry.py` δηλώνει τις λειτουργικές ενότητες, factories και μεταδεδομένα πλοήγησης. Η σειρά δημιουργίας σελίδων και η διαφορετική σειρά sidebar διατηρήθηκαν.
- Το `contracts.py` ορίζει τα `ModuleDefinition` και `PageActions`. Οι σελίδες/διάλογοι δεν αναζητούν πλέον αδελφές σελίδες μέσω `window().pages`.
- Ο χειρισμός βάρδιας απομονώθηκε στον `features/shifts/controller.py`. Το `workflows.py` κρατά την ίδια σειρά κλεισίματος, αρχειοθέτησης και backup, συμπεριλαμβανομένης της συμπεριφοράς σε αποτυχία.
- Δεν προστέθηκαν επιχειρησιακές λειτουργίες, ασύγχρονες ροές, δυναμική ανακάλυψη plugins ή νέα μορφή αποθήκευσης.
- Τα source-contract tests ακολουθούν τη νέα θέση της πραγματικής υλοποίησης. Τα tests που έλεγχαν την παλιά κατασκευή πλοήγησης ελέγχουν πλέον το registry. Δεν αφαιρέθηκε καμία ιστορική δοκιμή ούτε μετατράπηκε αποτυχία σε skip/xfail.

## Windows EXE και όρια αποδοχής

Υλοποιήθηκε αποκλειστικό workflow `modular-phase1-validation.yml`, με έλεγχο αρχικού και νέου source στα Windows, σύγκριση αποτελεσμάτων/UI/εγγράφων, build από το αμετάβλητο spec και εξωτερικό λειτουργικό έλεγχο του frozen EXE. Ο τελευταίος χρησιμοποιεί native UI Automation, προσωρινό αντίγραφο του EXE και συνθετικά δεδομένα: έναρξη βάρδιας, πλοήγηση έξι σελίδων, κλείσιμο, έλεγχος SQLite και παραγόμενου Excel.

Τα αποτελέσματα ανά ακριβές source SHA αποθηκεύονται στο ξεχωριστό branch `validation/control-center-modular-phase1`, ενώ το δοκιμαστικό EXE ανεβαίνει μόνο ως Actions artifact. Ο μηχανισμός καταγραφής επαληθεύτηκε τοπικά με δύο διαδοχικές εκτελέσεις σε συνθετικό Git remote: διατηρεί το source HEAD/index και συμπεριλαμβάνει το build log.

**Η κατάσταση του πραγματικού Windows run καταγράφεται χωριστά από τα τοπικά PASS.** Το μηχάνημα ανάπτυξης είναι Linux και η πρόσβαση στο Actions API αποκλείεται· η ανάκτηση γίνεται μέσω του evidence branch. Πραγματική διασύνδεση με εγκατεστημένο Word/Excel, εκτύπωση και επιτόπια αποδοχή δεν πιστοποιούνται από το headless Linux ή το Windows runner χωρίς Office.

Καμία παραγωγική δημοσίευση, merge ή αντικατάσταση λειτουργικής έκδοσης δεν επιτρέπεται χωρίς νέα έγκριση.

### Παρατηρημένη εκκρεμότητα Windows

Στο τρέχον cloud περιβάλλον οι HTTPS κλήσεις προς `api.github.com` απορρίπτονται με `CONNECT 403`, ενώ η αυθεντικοποιημένη πρόσβαση Git λειτουργεί. Τα pushes στο branch υλοποίησης επιβεβαιώθηκαν. Μέχρι τη σύνταξη της αναφοράς δεν έχει ανακτηθεί ούτε ένδειξη έναρξης ούτε τελικό αποτέλεσμα από το προβλεπόμενο evidence ref. Συνεπώς **δεν επιβεβαιώνεται εκτέλεση Actions, επιτυχία build, δημιουργία artifact ή λειτουργική επιτυχία Windows EXE**. Η απουσία αποτελέσματος δεν αποδεικνύει την αιτία ή ότι δεν υπάρχει απομακρυσμένη εκτέλεση.

Για να ολοκληρωθεί αυτή η απαίτηση χρειάζεται προσβάσιμη εκτέλεση/αποτέλεσμα του workflow «CONTROL CENTER modular Phase 1 validation» ή δυνατότητα ανάγνωσης των Actions στο διαθέσιμο GitHub περιβάλλον. Δεν απαιτείται έγκριση για επόμενη μεταφορά κώδικα· εκκρεμεί μόνο εξωτερικό τεκμήριο/δυνατότητα Windows. Η αρχιτεκτονική δεν παρουσιάζεται ως συνολικά πιστοποιημένη για παραγωγική χρήση όσο αυτό παραμένει ανοιχτό.
