## Στάδιο Α — πριν από αλλαγές εφαρμογής

Οι αναπαραγωγές έγιναν αποκλειστικά σε TemporaryDirectory, με συνθετικά bytes, πραγματικές SQLite και πραγματική παραγωγή DOCX/XLSX. Δεν εκτελέστηκε ενέργεια σε υπηρεσιακή διαδρομή, email ή ERMIS.

| Περιοχή | Αναπαραχθέν εύρημα |
|---|---|
| SCAN | Το normalize επιβάλλει τρεις χωριστές σειρές και YEAR_MONTH, χάνοντας τον κοινό ημερήσιο φάκελο. Με κοινό root η αναζήτηση δεν φιλτράρει ανά τύπο: και οι τρεις ορισμοί επιλέγουν Εγκληματικότητα. Το dedup ανά root προετοιμάζει 1 αντί 3 αρχεία. |
| Ημερήσια Κίνηση | Η υπηρεσία φορτώνει το αποθηκευμένο runtime profile, όχι ξανά το αρχικό JSON. Σε συνθετικό αποθηκευμένο profile διατηρεί το παλιό root κάτω από SHARED_FILES. Το πραγματικό profile του φυσικού υπηρεσιακού σταθμού δεν έχει παρασχεθεί και δεν παρουσιάζεται ως ελεγμένο. |
| Βήμα 3 | Το UI καλεί refresh μετά το sync και ξανακλειδώνει το Βήμα 3. Το engine αντικαθιστά επεξεργασμένο μη απεσταλμένο managed copy στο δεύτερο sync και διαγράφει το προηγούμενο στην επόμενη ημερομηνία. |
| Πληρωμές/ημερήσια | Η Εφορία είναι TYPOU_A στη FineEntry.daily_identity αλλά cash στη DailyActivityService. Άγνωστοι/κενοί τρόποι ταξινομούνται ως cash. Μετρητά και Δ.Ε. Τύπου-Α έχουν διαφορετική αναγνώριση μεταξύ συναρτήσεων. |
| Απευθείας είσπραξη | Η add_receipt δημιουργεί action/receipt αλλά όχι fine. Η ημερήσια διαβάζει μόνο fines και δεν τη μετρά. Απαιτείται συνδυασμός πηγών με dedup ανά action_id, χωρίς επανεγγραφή ιστορικών δεδομένων ή τεχνητά πρόστιμα. |
| Έγγραφα | Νέο κλειστό DOCX προστίμων και XLSX ημερήσιας περιέχουν δήλωση «υπογράφηκε ηλεκτρονικά». Υπάρχει ίδιο κείμενο στο ΒΑΣ. Οι πραγματικές timestamps βάρδιας λειτουργούν ήδη σωστά και διατηρούνται. |
| Word εμφάνιση | Η γεννήτρια αντιγράφει την υπάρχουσα μορφοποίηση των 11 στηλών. Η αλλαγή θα περιοριστεί στις γραμμές της κάτω ενότητας, με έλεγχο XML ταυτότητας όλης της άνω ενότητας. |
| Έκδοση | APP_VERSION και VERSION.txt παραμένουν 1.0.14 και το spec δεν ορίζει Windows version resource. Απαιτείται πραγματικό νέο build και διασταύρωση όλων των ταυτοτήτων· καμία μετονομασία παλιού EXE. |

Τα συνθετικά raw αποτελέσματα είναι στο `field-corrections-diagnosis.json`. Τα παλιά SCAN αρχεία διατηρήθηκαν byte-for-byte στις δοκιμές. Αυτό είναι αρχική διάγνωση, όχι ολοκλήρωση υλοποίησης ή πιστοποίηση νέου EXE.
